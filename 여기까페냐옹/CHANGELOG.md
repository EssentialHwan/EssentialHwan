# 개발 결정 기록 (Decision Log)

시간순 주요 결정. 각 결정의 "왜"를 남겨 나중에 뒤집지 않도록 한다.

## 기획 확정
- **핵심 재미 = 정보 비대칭 해소**: 숨겨진 취향(Truth)을 행동 관찰로 역추론. "돈"이 아니라 "이해"를 판다.
- **Truth ↔ Observed 물리적 분리**: 세이브·UI에 Truth 없음. 오추론 유도가 재미의 일부.

## 검증 후 수정 (P1~P10)
- **P1** fallback 단서 weight 0.5 + cap 2 → 가짜 가설("일반석 선호") 차단. *왜: fallback이 오추론 재료로 쌓여 좌절 유발하던 문제.*
- **P2** 분위기를 독립 관찰 축에서 제외 → 좌석/시설 만족 승수(MVP는 무영향). *왜: 초반에 죽은 축 + 인지 부하. 관찰 3축으로 단순화.*
- **P3** 카페 성장에 OR 대체 경로. *왜: 관찰 실패 시 골드가 넘쳐도 영구 데드락 위험.*
- **P4** 추론 4단계(?→…→★→✓). *왜: "자동 Confirmed"와 "플레이어 기록" 규칙 충돌 해소.*
- **P5** 만족도 satisfactionHistory 단일 소스. *왜: 3곳 중복 필드 불일치 위험.*
- **P6** SeatSelectionScore/SeatSatisfactionBonus 명명 분리. *왜: 동명이개념 혼동.*
- **P7** maxSitDuration + 회전율 압박 제거. *왜: "빨리 내보내기"가 관찰 게임 역행.*
- **P8** MVP 축소(관계·상황·MoveSeat/Social 제외). *왜: 코어 무관 + 개발기간.*
- **P9** 발견 성공 연출. *왜: 첫 세션 인과 학습.*
- **P10** 음식 favorite만(MVP), 계열은 정식. *왜: 초기 구분 난이도 대비 비용.*

## 출시 다이어트 (1.0)
- **"깊게 8마리 > 얕게 20마리"**: 넓이 포기, 코어 밀도 유지.
- **삭제 부활 금지**: 온라인·BM·이중재화·직원·조리미니게임·계절·관계그룹·사진모드·워크샵.
- **S1 게이트 철칙**: 관찰 재미 검증 실패 시 S2 진행 금지.

## 구현 (S1~S3 + 정식)
- S1 코어(관찰 파이프라인·행동AI·fallback·4단계 추론) 완성.
- S2 정식 확장: 분위기 승수·음식 2계층·손님 곡선·데이터주도 성장.
- S3 콘텐츠: 해금(UnlockCondition/Service)·이벤트(에피소드)·서술 세분화.
- 정식 관계 시스템(RelationshipManager) + 친구→좌석선택 반영.
- 전 시스템 배선(성장→해금→스폰, 발견→곡선, 관계→좌석).
- EditMode 66 테스트 통과(dotnet 헤드리스 검증). 10일 다일 시뮬 포함. (Unity Test Runner 실행 결과는 M1 씬 셋업 후 별도 확보 예정)
- [프리플라이트 수정] 좌석 부분일치·좌석 AI 분위기 보너스 제거, 재방문 판정을 '지난 방문 실제 결과'로, 단골 고정자리(favoriteSeat) 포스트 MVP로 이동, 가구 18개(좌석6)로 통일.
- 콘텐츠 생성기·로컬라이즈(한/영)·UI 뷰 헬퍼·데브콘솔·이동 추상화.
- 남은 것: Unity 에디터 씬 배선·NavMesh·UI 위젯·아트·PlayMode 테스트·Steam (실제 Unity 필요).

## 결정: 왜 코드를 이렇게까지 완성했나
- 1인+AI 개발에서 최대 리스크는 "로직이 맞물려 도는지 늦게 발견"하는 것.
- 씬/아트 없이도 dotnet 헤드리스 테스트로 전 시스템을 사전 검증 → M1에서 배선만 하면 되게 함.
- 순수 로직(static Evaluate 등)으로 분리해 테스트 가능성 극대화.
