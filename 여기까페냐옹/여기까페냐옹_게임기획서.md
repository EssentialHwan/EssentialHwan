# 《여기까페냐옹》 게임 시스템·콘텐츠 개발 기획서

> **문서 성격**: 아이디어 문서가 아니라 Unity 개발 착수용 시스템/콘텐츠 기획서
> **대상 독자**: 기획자 본인 + 실제 구현할 Unity 개발자 + 코드 생성에 사용할 AI
> **엔진 전제**: Unity (C#), PC/Steam 우선, 싱글플레이
> **개발 규모**: AI를 적극 활용하는 1인~소규모 개발
> **작성 원칙**: 추상 금지. "어디서 값을 가져오는지 / 언제 판정하는지 / 무엇을 저장하는지 / 무엇을 플레이어에게 보여주는지 / 예외 처리"를 항상 명시. 미확정은 `[미결정]`으로 표기하고 선택지를 제시한다.

---

## 문서 사용 규약 (개발자·AI가 먼저 읽을 것)

- **숨겨진 값(Truth)** 과 **관찰값(Observed)** 은 절대 같은 필드가 아니다. 코드에서 서로 다른 데이터 구조로 분리한다.
- 플레이어 UI는 **Truth 필드에 직접 접근 금지**. 오직 `ObservationRecord`(관찰 기록)만 읽는다.
- 모든 콘텐츠(고양이/가구/메뉴/이벤트)는 **ScriptableObject 데이터**로 추가하며, 새 콘텐츠 추가 시 매니저 코드 수정이 없어야 한다.
- 태그 기반 매칭을 기본으로 한다. 하드코딩된 if 분기(예: `if (cat == 치즈냥)`)를 금지한다.
- 종전 `[미결정]` 항목(A~J)은 **전부 확정**되었다. 최종 결정은 **부록 J(확정 사항)** 표를 기준으로 한다.

## 01. 게임 개요

**[한 문장 설명]**
> 인간이 사라진 고양이들의 세계에서, 플레이어 고양이가 카페를 운영하며 **손님 고양이의 행동을 관찰하고 숨겨진 취향을 추리해, 카페를 그 고양이에게 맞게 바꿔가는** 관찰·추리형 카페 경영 시뮬레이션.

**[장르]** 고양이 카페 경영 시뮬레이션 (+ 관찰 / 취향 추리 / 캐릭터 관계 / 가벼운 수집 / 생활 시뮬)

**[핵심 한 줄 기획 의도]**
"돈을 벌었다"가 아니라 **"내가 이 고양이를 이해했다"** 는 감정을 파는 게임.

**[플랫폼]** PC/Steam 우선. 모바일은 향후 검토(현재 개발 기준 아님).

**[규모 원칙]** 온라인/서버/과도한 콘텐츠 배제. 1인+AI로 완성 가능한 규모.

## 02. 게임의 핵심 재미

**[핵심 루프 (감정 단위)]**
```
관찰 → 추론 → 카페 변경 → 행동 변화 → 새로운 관찰
   → 취향 발견 → 만족도 증가 → 재방문/단골 → 새 행동·이야기 → 카페 성장
```

**[핵심 재미 정의]**
- 재미의 원천은 **"정보의 비대칭 해소"** 다. 게임은 고양이의 진짜 취향(Truth)을 숨기고, 플레이어는 행동만 보고 이를 역추론한다.
- **가구는 추론 도구**다. 카페에 없는 대상은 관찰조차 불가능하므로, 가구 구매는 "능력치 상승"이 아니라 "관찰 채널 개방"이다.

**[감정 우선순위 규칙 (모든 시스템이 지켜야 함)]**

| 약한 감정(피해야 할 것) | 강한 감정(목표) |
|---|---|
| "돈을 많이 벌었다" | "이 고양이를 이해했다" |
| "가구를 샀다" | "이 가구를 놓으니 행동이 달라졌다" |
| "단골 수치가 올랐다" | "저 고양이가 이제 매일 이 자리에 앉는다" |

**[설계 제약]** 어떤 시스템이든 우측 감정을 강화하지 못하면 재검토한다.

## 03. 플레이어 경험 (시간대별 목표 곡선)

| 플레이 시점 | 목표 심리 |
|---|---|
| 시작 | "귀여운 고양이들이 있네." |
| ~30분 | "어? 치즈냥이 창가를 좋아하나?" (첫 가설) |
| ~1시간 | "창가석 사볼까?" → 설치 → "진짜 좋아하네." (첫 검증 성공) |
| ~2시간 | "삼색냥은 캣타워?" → 구매 → 행동 변화 → "얘 진짜 호기심 많구나." (성격·취향 분리 체감) |
| 장기 | "자주 오는 애들이 생겼다" / "얘네 둘이 친해졌네" / "이 카페가 내가 만든 카페 같다." |

**[경험 설계 KPI]** 첫 세션 내 최소 1회의 "가설→구매→검증 성공" 사이클을 반드시 경험시킨다. (튜토리얼 46장에서 강제)

## 04. 차별점

**[일반 경영게임과의 차이]**

| 항목 | 일반 카페게임 손님 | 《여기까페냐옹》 고양이 |
|---|---|---|
| 정체성 | 돈 지불 NPC | 게임의 핵심 콘텐츠 |
| 취향 | 없음/단순 | 고정된 숨겨진 취향 |
| 행동 | 주문→퇴장 | 성격·환경 기반 자율 행동 |
| 관계 | 없음 | 고양이 간 관계 형성 |
| 성장 | 매출 그래프 | 단골 단계별 이야기 변화 |

**[핵심 차별 문장]** 손님이 **"손님 데이터"가 아니라 "해독해야 할 퍼즐이자 캐릭터"** 다.

## 05. 세계관

- 인간이 사라진 뒤 고양이가 인간 문명을 계승. 고양이는 말하고, 도시를 세우고, 상점·카페를 운영한다.
- 플레이어도 고양이이며 자신의 카페를 운영한다.
- **스토리 중심 게임이 아니다.** 세계관은 "왜 카페를 하는가 / 왜 고양이가 이렇게 행동하는가"의 배경 설명 역할.
- **개발 반영**: 대사·이벤트 텍스트의 톤은 가볍고 따뜻하게. 세계관 전달은 도감·단골 에피소드·환경 소품으로 분산(컷신 최소화).

## 06. 전체 게임 루프

**[매크로 루프 (하루 단위)]**
```
영업 준비(메뉴·배치 확인) → 영업 시작 → [고양이 방문 → 좌석선택 → 주문 → 조리 → 서빙
  → 식사 → 시설이용 → 상호작용 → 퇴장 → 관찰정보 축적] × N
  → 영업 종료 → 오늘의 관찰 정리 → 취향 기록 → 매출 정산
  → 구매(가구/시설/메뉴) → 카페 환경 변경 → 다음 날
```

**[루프 연결 규칙 (43장 핵심)]** 아래 체인은 절대 끊기지 않는다:
```
고양이 취향(Truth) → 행동 AI → 관찰 → 취향 기록 → 만족도 → 재방문 → 단골 → 관계 → 이벤트 → 카페 성장 → (새 가구로) 새로운 관찰 채널 → 취향
```
각 화살표는 실제 데이터 전달이며, 담당 매니저와 저장 필드가 41·42·39장에 명시된다.

## 07. 하루 게임 루프

**[목적]** 하루를 시간대 리듬으로 구성해 관찰 밀도와 난이도를 조절.

**[핵심 규칙]**
- 게임 내 하루 기본 길이: **12분** (`DayLengthSeconds = 720`, 밸런스 조정 대상).
- 3개 시간대: 아침 / 점심 / 저녁. **분할 확정: 3:4:5분(저녁 강조)** — 특별 손님·최다 방문을 저녁에 배치(부록 J-A).

**[게임 처리 — 시간대별 파라미터]**

| 시간대 | 길이 | 손님 스폰 간격(초) | 음료:음식 주문 비율 | 특징 |
|---|---|---|---|---|
| 아침(Morning) | **3분** | 넓음(예 20s) | 70:30 | 여유, 소수 방문 |
| 점심(Lunch) | **4분** | 보통(예 12s) | 40:60 | 손님 증가, 복수 주문 확률↑ |
| 저녁(Evening) | **5분** | 좁음(예 9s) | 40:60 | 최다 방문, 특별 손님 등장 가능 |

- `DayManager`가 `currentPhase`를 관리하고, `CustomerSpawner`가 phase별 스폰 테이블을 참조.
- 시간대 전환 시 `OnPhaseChanged(phase)` 이벤트 발행 → 스폰·이벤트·연출이 구독.

**[플레이어에게 보이는 정보]** 상단 시계/시간대 아이콘, 남은 시간 바, 현재 손님 수.

**[숨겨진 정보]** 다음 스폰 예정 고양이 큐, 특별 손님 등장 롤 결과.

**[예외 처리]**
- 영업 종료 시각 도달 시 신규 스폰 중단, 매장 내 고양이는 현재 행동을 마치고 순차 퇴장(강제 종료 X).
- 좌석이 모두 만석이면 신규 고양이는 **성격별 분기(확정, 부록 J-B)**: 느긋함/내향적 → `WaitOutside`(대기, 자리나면 입장), 활발/변덕/호기심 → `LeaveDisappointed`(귀가, 재방문확률 소폭↓).

**[핵심 규칙 — 회전율 압박 제거(P7)]** 이 게임은 관찰 게임이므로 **좌석 회전율 압박을 만들지 않는다.** 스폰 총량을 항상 좌석 수보다 여유 있게 설계해, 느긋한 고양이가 오래 앉아도 "빨리 내보내기" 플레이가 강요되지 않게 한다. 좌석 부족은 **패널티가 아니라 카페 성장(31장) 유인**으로만 사용. (느긋함의 `sitDuration ×1.5`가 매출 압박이 되지 않도록 함 — 12장 참조)

**[밸런스]** 위 수치는 전부 **초기 테스트용 가정값**. 하루 손님 총량 목표: MVP 아침 3 / 점심 5 / 저녁 6 ≈ 14마리(중복 방문 포함). **동시 체류 상한 < 좌석 수**가 되도록 스폰 간격을 조정.

**[개발 고려사항]** 시간은 `Time.deltaTime` 누적이 아니라 `dayTimer`(일시정지·배속 지원) 기반으로 구현. 배속(1x/2x/3x)은 관찰 편의를 위해 제공 권장.

## 08. 고양이 시스템 (총괄)

**[목적]** 고양이를 "핵심 콘텐츠"로 구현. 데이터 주도 + 상태기반 AI + 관찰 대상.

**[구성 요소]**
1. `CatData` (ScriptableObject, Truth 정의)
2. `CatInstance` (런타임 상태: 위치, 현재 상태, 세션 로그)
3. `CatBrain` (행동 AI: FSM/BT)
4. `CatSaveData` (영속 데이터: 방문 횟수, 만족도 이력, 단골 단계, 관계, 관찰 기록)

**[핵심 규칙 요약]**
- 취향은 **고정**(런타임 변경 금지).
- 취향 대상이 카페에 없으면 **fallback 행동**을 하며, 이는 취향이 아니다.
- 취향은 **행동으로만** 플레이어에게 노출된다.

**[데이터-인식 분리]**
```
Truth:    CatData.SeatPreference = Window
런타임:   CatInstance.chosenSeat = Normal (창가석 없어서 fallback)
관찰기록: ObservationRecord[치즈냥].seatClues += {NormalSeat weight +0.5, cap 2}
          // fallback 단서는 약하고 상한이 있어(17장 P1) Suspected(≥3)로 승격되지 않음
          // → "일반석 선호"라는 가짜 가설이 생기지 않고, 좌석 축은 '?'에서 정체 → 새 좌석 구매 유도
```

| `atmospherePreference` | AtmosphereTag | 선호 분위기 | **숨김(Truth)** |

## 10. 고양이 성격 (Personality)

**[목적]** 성격은 **행동 방식(How)**, 취향은 **선호 대상(What)**. 둘은 독립 축이다.

**[성격 태그 → 행동 가중치 매핑]**

| PersonalityTag | 행동 영향(구현식 반영) |
|---|---|
| Relaxed(느긋함) | `sitDuration ×1.5`, 상태전환 확률↓ |
| Curious(호기심) | 신규 시설 이용확률 `+0.3`, 자리 탐색확률↑ |
| Social(사교적) | 좌석선택 시 `SocialScore` 가중치 ×2 |
| Lonely(외로움) | 주변 고양이 0마리면 만족도 `-10`, 근접 좌석 선호 |
| Active(활발함) | 시설 이용 빈도↑, 앉은 시간↓ |
| Introvert(내향적) | 혼잡할수록 만족도↓, 구석 선호 가중 |
| Glutton(식탐) | 추가 주문 확률↑, 음식 만족 가중치↑ |
| Playful(장난꾸러기) | 놀이 태그 시설 이용확률↑ |

**[핵심 규칙]** 성격과 취향은 상관관계를 강제하지 않는다. (호기심 고양이가 캣타워를 반드시 좋아하지 않음)

**[관찰 — 확정, 부록 J-C]** **성격1(`personalityTags[0]`)은 첫 방문 시 도감에 즉시 공개**되어 초기 추론의 발판이 된다. **성격2(`personalityTags[1]`)는 관련 행동을 관찰해야 공개**된다. (취향 4축과 달리 성격은 진입 접근성을 위해 절반을 즉시 제공)

## 11. 고양이 취향 (Preference / Truth)

**[핵심 규칙]**
- 취향은 4축: **음식 / 좌석 / 시설 / 분위기**.
- 음식은 2계층: `foodFavorite`(특정 메뉴) + `foodPreferredTags`(계열).
- 취향은 **고정**, 런타임에 절대 바뀌지 않는다.

**[프로토타입 3종 Truth 표]**

| 고양이 | 성격 | 음식(최애/계열) | 좌석 | 시설 | 분위기 |
|---|---|---|---|---|---|
| 치즈냥 | 느긋함, 식탐 | 생선케이크 / Fish | 창가석(Window) | 쿠션(Soft/Relax) | 조용함 |
| 삼색냥 | 호기심, 변덕 | 딸기파르페 / Sweet | 구석석(Corner) | 캣타워(Play/Height) | 활기참 |
| 젖소냥 | 사교적, 외로움 | 참치샌드위치 / Fish,Meal | 2인석(TwoSeat) | 장난감바구니(Play/Social) | 활기참 |

**[만족 판정]** 취향 만족 = 실제 이용 대상이 Truth와 **태그 매칭**되는지로 판정(25장 만족도 계산에 연결).

## 12. 고양이 행동 AI (CatBrain)

**[목적]** 순서대로만 행동하지 않고, 성격·환경에 따라 다양한 행동을 하게 만들어 **관찰거리**를 생성.

**[구현 방식 — 확정, 부록 J-D]** **계층적 상태기계(HFSM)** 로 구현한다. 상태 전이는 HFSM이 담당하고, **분기점(Sit/Eat 이후 행동 선택)에서만 Utility 점수식(ActionScore, 아래)** 을 사용한다. Behavior Tree는 채택하지 않는다(1인 개발 난이도·툴 부담).

**[상태 목록]**
```
Enter → FindSeat → Sit → DecideOrder → Order → WaitFood → Eat
      → (분기) FacilityAction / SocialAction / Idle(관찰·휴식) / MoveSeat
      → Pay → Leave
```

**[분기 규칙 (Sit/Eat 이후 매 tick 판정)]**
매 결정 주기(예 3초)마다 후보 행동의 점수를 계산해 확률적으로 선택:
```
ActionScore(action) =
    baseWeight[action]
  + personalityBonus[action]          // 10장 매핑
  + environmentBonus[action]          // 선호 시설 존재 시 가중
  + relationshipBonus[action]         // 친구 근처면 Social↑
  - repeatPenalty[action]             // 직전 동일행동 반복 억제(39장 8번 대응)
  + Random(-r, +r)
```
가장 높은 점수 행동을 실행. `repeatPenalty`로 "같은 행동만 반복"을 방지.

**[상태별 정의 (요약)]**

| 상태 | 진입조건 | 처리 | 종료조건 |
|---|---|---|---|
| Enter | 스폰 | 입구 등장, 좌석탐색 시작 | 좌석 후보 수집 완료 |
| FindSeat | Enter 후 | 13장 SeatScore 계산 | 좌석 확정/포기 |
| Sit | 좌석 확정 | 착석, sitDuration 설정 | 주문 결정 |
| DecideOrder | 착석 후 | 메뉴 선택(취향 반영) | 주문 확정 |
| WaitFood | 주문됨 | 대기, 대기시간 누적(만족도-) | 서빙 완료 |
| Eat | 서빙됨 | 식사(속도=성격) | 식사 완료 |
| FacilityAction | 분기 | 선호/근접 시설 이용 | 시간만료 |
| SocialAction `[MVP: 제외]` | 분기 | 근처 고양이와 상호작용 | 시간만료 |
| MoveSeat `[MVP: 제외 → Phase2]` | 분기(변덕 등) | 더 높은 점수 좌석으로 이동 | 이동완료 |
| Pay | sitDuration 만료 | 결제(만족도→금액) | 완료 |
| Leave | Pay 후 | 퇴장, 세션로그 확정 | 디스폰 |

**[MVP 상태 축소 (P8)]** MVP FSM은 `Enter → FindSeat → Sit → DecideOrder → Order → WaitFood → Eat → (FacilityAction / Idle) → Pay → Leave`. `SocialAction`·`MoveSeat`·관계 분기는 Phase 2 이후.

**[sitDuration 상한 (P7)]** `sitDuration = base × personalityFactor` 이되 **절대 상한 `maxSitDuration`** 을 둔다(느긋함이어도 무한 점유 금지). Pay는 `min(sitDuration, maxSitDuration)` 만료 시 발생. 회전율 압박은 만들지 않되(7장), 단일 고양이의 자리 독점도 방지.

**[관찰 훅]** 각 상태·행동은 실행 시 `ObservationManager.RecordClue(catId, clueType, target)` 를 호출해 관찰 단서를 남긴다.

**[예외 처리]**
- 좌석 없음: `FindSeat` 실패 → 7장 성격별 분기 규칙(부록 J-B) 적용.
- 서빙 지연 임계 초과: `Leave`(불만) 분기, 만족도·매출 페널티.

## 13. 좌석 시스템

**[목적]** 취향·성격·상황을 좌석 선택으로 표현 → 가장 관찰하기 쉬운 취향 축.

**[좌석 종류]** 일반석 / 창가석 / 구석석 / 2인석 / 소파 / 바테이블. 각 좌석은 `SeatTag[]` 보유.

**[핵심 규칙 — fallback]**
```
1) 카페 내 '이용 가능(빈)' 좌석을 모두 후보로 수집
2) 각 후보의 SeatScore 계산
3) 최고 점수 좌석 선택
4) 선호 좌석이 없거나 만석이면 → 차순위 좌석 선택 (이것은 취향 아님!)
```

**[SeatSelectionScore 계산식 (구현 확정안, P6 명명 분리)]**
> 좌석 **선택**용 점수 `SeatSelectionScore`는 만족도용 `SeatSatisfactionBonus`(25장)와 이름·개념이 완전히 다르다. 혼동 방지를 위해 전역 명명을 분리한다.
```
SeatSelectionScore =
    PreferenceScore     // 좌석태그가 Truth.seatPreference와 일치 +100, 부분일치 +40, 무관 +10
  + PersonalityScore    // 내향적: 구석/조용 +30, 사교적: 중앙 +20
  + AtmosphereScore     // 좌석 주변 국소 분위기가 취향과 일치 +20 (MVP 생략 가능)
  + SocialScore         // 친구가 인접 +40, 낯선 다수 인접 (내향)−20/(사교)+15
  − DistancePenalty     // 입구~좌석 거리 × 계수(예 −0.5/유닛)
  + Random(−10, +10)
```
- **동점/근소차 방지**: Random 편차로 동일 조건 반복 선택을 피함(관찰 다양성).
- 계산은 `SeatSelector.Evaluate(catInstance)` 정적 로직으로 구현, 좌석 추가 시 코드 수정 불필요(태그로만 동작).

**[플레이어에게 보이는 정보]** 고양이가 특정 좌석으로 이동/착석/오래 머무름.
**[숨겨진 정보]** SeatSelectionScore 각 항목 값, Truth 선호.

**[밸런스(가정값)]** 위 상수는 초기값. PreferenceScore 지배력이 성격·랜덤을 압도하도록 유지(취향 신호가 노이즈에 묻히면 추리 불가).

**[예외]** 모든 좌석 만석 → 대기/포기(7장). 사용 중 좌석은 후보 제외.

## 14. 시설 시스템 (Facility)

**[목적]** 앉기 외 행동을 만들어 취향 축(시설·놀이·휴식)을 관찰 가능하게 함.

**[시설 종류]** 캣타워 / 쿠션 / 장난감바구니 / 스크래처 / 화분 / 창문. 각각 `FacilityTag[]` + `FacilityAction[]`.

**[핵심 규칙 — "가구가 있어야 취향 관찰 가능"]**
```
선호 시설이 카페에 없음 → 그 취향 행동은 절대 발생하지 않음 → 관찰 불가 → 도감 '?' 유지
선호 시설 설치됨 → 이용확률↑ → 선호 행동 발생 → 관찰 → 기록 가능
```
이 규칙이 "가구=관찰 채널"의 핵심. `FacilityUseChance`:
```
UseChance(cat, facility) =
    base(0.15)
  + (facility.tags ∩ cat.facilityPreference ? +0.5 : 0)
  + (Curious ? +0.3 : 0) + (Playful & Play태그 ? +0.3 : 0)
  − recentUsePenalty
```

**[FacilityAction 예]** 캣타워: `ClimbTop`, `Watch`; 쿠션: `Sleep`, `Knead`; 장난감바구니: `PlaySolo`, `PlayWithFriend`.

**[관찰 훅]** 시설 이용 시 `RecordClue(catId, Facility, facilityTag)`.

**[예외]** 시설 점유 중이면 대기/다른 행동. 시설 파손·업그레이드는 MVP 제외.

## 16. 카페 분위기 (Atmosphere)

> **P2 반영 — 역할 재정의**: 분위기를 "제4의 독립 관찰 축"으로 두면 초반에 어떤 축도 지배적이지 않아 사실상 죽은 시스템이 되고, 관찰 축이 4개라 인지 부하도 크다. 따라서 **분위기는 독립 취향 축에서 제외**하고, 좌석·시설 만족을 강화하는 **승수(modifier)이자 "카페 꾸미기 보상"** 으로 재정의한다.
> - 관찰·추론·기록 대상 축은 **음식 / 좌석 / 시설 3축**으로 확정.
> - `atmospherePreference`(Truth)는 데이터로 유지하되, 관찰·기록 UI에는 노출하지 않는다.

**[목적]** 카페 전체 톤을 만들고, 고양이의 선호 분위기와 맞을 때 좌석·시설 만족을 **소폭 증폭**시켜 "공간을 꾸미는 재미"를 보상.

**[분위기 축]** 조용함 / 활기참 / 따뜻함 / 자연스러움 / 고급스러움.

**[계산식]**
```
Atmosphere[axis] = Σ (배치된 가구.atmosphereContribution[axis])   // 전역
DominantAxis = argmax(Atmosphere[*])                             // 절대값 아닌 '상대 최댓값' 축
  · 모든 축이 임계 미만이거나 1·2위 동률이면 DominantAxis = None(중립)
LocalAtmosphere(seat) = 전역 + 인접(반경 r) 가구 보정            // 좌석 국소값(정식 확장)
```
지배 분위기는 **상대 최댓값**으로 판정(초반 저값 문제 해소). **확정(부록 J-E): MVP는 전역만, 국소(`LocalAtmosphere`)는 정식 버전 확장.**

**[가구 기여 예]**

| 가구 | 기여 |
|---|---|
| 창가석 | 자연스러움+3, 조용함+2 |
| 쿠션 | 따뜻함+3, 조용함+2 |
| 캣타워 | 활기참+4 |
| 고급소파 | 고급스러움+5, 따뜻함+1 |

**[만족 반영 — 승수 방식(P2)]** 고양이 `atmospherePreference`와 `DominantAxis`가 일치하면 **그 고양이의 좌석·시설 만족 기여에 ×1.1 증폭**(별도 가산 축 아님). 반대 분위기면 ×0.9. 중립(None)이면 ×1.0.
```
FinalSeatSatBonus = SeatSatisfactionBonus × atmosphereMultiplier
FinalFacilitySatBonus = FacilityScore × atmosphereMultiplier
atmosphereMultiplier: 일치 1.1 / 중립 1.0 / 반대 0.9
```

**[MVP 처리]** `[MVP: 만족도 미반영]`. MVP에서는 분위기를 **가구 꾸미기 시각효과·라벨 표시**로만 사용하고, 만족 승수는 정식 버전부터 적용. (관찰 3축 검증에 집중)

**[플레이어 정보]** 분위기 미터(5축 바) — 수치보다 "조용한 카페 / 활기찬 카페" 라벨을 크게 노출.

**[개발 고려]** 가구 배치/제거 시에만 재계산(매 프레임 X). 이벤트(비/축제)는 임시 보정치를 더함(29장).

## 17. 관찰 시스템 (Observation) — 게임의 심장

**[목적]** Truth를 직접 노출하지 않고, **행동 단서(Clue)** 를 축적·정리해 플레이어가 추론하게 함.

**[데이터 흐름]**
```
CatBrain 행동 실행 → RecordClue(catId, ClueType, targetTag/id, phase)
  → 세션 로그(CatSessionLog)에 누적
  → 영업 종료 시 '오늘의 관찰 정리'로 요약
  → 플레이어가 '취향 기록'으로 확정 → ObservationRecord(영속) 갱신
```

**[ClueType]** SeatUse / FacilityUse / FoodEat(속도·완식여부) / AtmosphereReaction / SocialAction / IdleGaze(창밖 응시 등).

**[Clue 강도]** 각 단서는 `weight`를 가짐. 예: "생선케이크 남김없이 빠르게 완식" = 강한 음식 단서(+3), "일반석 앉음(fallback)" = 약한 좌석 단서(+0.5). fallback 행동도 단서로 남지만 **약하게** 남겨 오추론 후 정정이 가능하게 함.

**[핵심 규칙 — fallback 단서 상한(P1 반영)]**
fallback 행동(선호 대상이 없어 차선을 택한 경우)의 단서는 **축별 누적 상한 cap = 2** 를 둔다.
```
fallback SeatUse weight = +0.5, 누적 cap 2  →  Suspected 임계(3) 도달 불가
```
- 효과: 창가석 미설치 상태에서 치즈냥이 일반석에 계속 앉아도, 일반석 좌석 단서는 최대 2에서 정체 → **가짜 가설("일반석 선호")이 Suspected로 승격되지 않는다.**
- 플레이어는 "좌석 취향이 뭔가 잡힐 듯 안 잡힌다"는 답답함을 느껴 새 좌석 구매를 시도(의도된 유도, 좌절 아님). 이 정체 상태가 18장 힌트 UI 트리거가 된다.
- **정상(선호 대상 존재) 단서는 cap 없음** → 창가석 설치 후 정상 승격.

**[핵심 규칙]** 카페에 대상이 없으면 관련 Clue는 아예 생성되지 않는다(15·14장).

**[플레이어 정보]** 실시간에는 말풍선/이펙트("치즈냥이 창밖을 오래 바라본다")로 서술형 표시. 수치 미표시.

**[숨겨진 정보]** clueType별 누적 weight, 확정 임계치.

## 18. 취향 추론 시스템 (Inference)

**[목적]** 여러 번의 관찰이 쌓여야 취향이 "확정 후보"로 승격되는 구조 → 반복 관찰 동기 부여.

**[확정 단계 모델 — 4단계 (축별 독립, P4 반영)]**
> 종전 3단계는 "weight로 자동 Confirmed"와 "플레이어가 기록해야 Confirmed"가 충돌했다. 시스템 판정과 플레이어 확정을 분리해 4단계로 확정한다.
```
Unknown(?) → Suspected(…) → Confirmable(★) → Recorded(✓)
   시스템 자동      시스템 자동         시스템 자동        플레이어 기록
```

**[승격 규칙 (구현 확정안)]**

| 상태 | 아이콘 | 조건 | 판정 주체 |
|---|---|---|---|
| Unknown | `?` | 초기 | — |
| Suspected | `…` | 특정 태그 누적 weight ≥ 3 | 시스템 자동 |
| Confirmable | `★` | 누적 weight ≥ 7 **그리고** 대안 태그 대비 우세(1위-2위 격차 ≥ 3) | 시스템 자동 ("기록 가능" 표시) |
| Recorded | `✓` | 플레이어가 관찰 정리에서 "기록" 클릭 | **플레이어** |

- **도감 ✓ = `Recorded` 상태만.** Confirmable(★)은 "기록할 수 있음"을 알리는 단계이며, 실제 확정·저장은 플레이어의 능동 행위(19장).
- fallback 단서(약함·cap2, 17장)만으로는 Suspected에도 도달하지 못해 오추론이 원천 차단된다.

**[플레이어 정보]** 도감에 축별 상태 아이콘(`?` / `…` / `★` / `✓`)과 근거 단서 텍스트 목록.

**[예외 — 오추론 정정 확정, 부록 J-F]** 선호 대상 미설치로 fallback만 반복되면 해당 축은 Suspected 미만에서 정체(17장 cap) → 힌트 UI로 "다른 환경을 시도해보라" 유도. 또한 **이미 `Recorded`된 축에 상충 단서가 강하게 누적되면(반증 임계 초과) 자동으로 `Suspected`로 강등**한다(힌트 유도 + 강한 반증 시 자동 강등).

## 19. 취향 기록 시스템 (Recording)

**[목적]** 발견을 **플레이어의 능동 행위**로 만들어 성취감 부여 + 세이브 확정.

**[게임 처리]** '오늘의 관찰 정리' 화면에서 각 고양이의 **Confirmable(★)** 상태 축에 대해 플레이어가 "기록" 버튼 클릭 → 상태 `Confirmable → Recorded(✓)` → `ObservationRecord` 갱신 → 도감 반영. (Suspected `…` 상태는 아직 기록 불가, "관찰이 더 필요해요" 표시)

**[발견 성공 연출 (P9 반영)]** 기록 성공 순간에만 명시적 보상 연출: 도감 칸이 `✓`로 채워지는 애니메이션 + "치즈냥의 취향을 하나 알아냈어요!" 토스트 + **소액 만족/골드 보너스**(수치는 계속 숨김, "발견=성공"의 인과만 강조). 46장 튜토리얼 1사이클과 연결.

**[저장]** `ObservationRecord`는 반드시 세이브(39장 필수 항목). Truth는 저장 안 함.

**[UI]** 관찰 정리 카드: 고양이별 [행동 요약] + [기록하기](Confirmable일 때만 활성) + [도감 보기].

**[예외 — 부록 J-F 확정]** 이미 `Recorded` 항목은 재기록 불가(중복 방지). 오기록 정정: 상충 단서가 반증 임계를 넘게 누적되면 **자동으로 `Suspected`로 강등**(힌트 유도 + 강한 반증 시 자동 강등).

## 24. 결제 시스템 (Payment)

## 25. 만족도 (Satisfaction)

**[목적]** 관찰·환경 조정의 성과를 수치화하고 재방문/단골로 연결.

**[100점 만점 계산식 (퇴장 시 확정, P2·P6 반영)]**
> 분위기는 독립 가산 축이 아니라 좌석·시설 만족의 **승수**(16장). 좌석 만족은 `SeatSatisfactionBonus`로 명명(선택용 `SeatSelectionScore`와 구분).
```
Satisfaction = clamp(
    base(50)
  + FoodScore                              // favorite +25 / preferredTag +15(정식) / 무관 +0 / 차선강제 −5
  + SeatSatisfactionBonus × atmoMult       // 선호좌석 이용 +15 / fallback +0
  + FacilityScore × atmoMult               // 선호시설 이용 +15 / 이용無 +0
  + SocialScore                            // 외로움+동반 +10 / 외로움+고립 −10 / 사교+친구 +10
  + ServiceScore                           // 빠른 서빙 +5
  − WaitPenalty                            // 대기 초과 초당 −k
  − OrderFailPenalty                       // 품절/실패 −10
, 0, 100)
// atmoMult: 선호분위기 지배 1.1 / 중립 1.0 / 반대 0.9   (MVP: 항상 1.0)
```
- **MVP**: `atmoMult = 1.0` 고정(16장). 관찰 3축(음식/좌석/시설) 충족으로 90+ 도달.
- FoodScore의 `preferredTag +15`는 정식 버전부터(P10). MVP는 favorite만 판정.

**[영향]** 결제 배수(24장), 재방문 확률(26장), 단골 진행(27장), 특별행동/이벤트 트리거.

**[플레이어 정보]** 퇴장 시 표정 아이콘(😻/🙂/😾) + 정산에 요약. 원수치 비노출.

**[밸런스]** 모든 상수 가정값. 취향 3축 충족 시 90+ 도달하도록 튜닝(이해=고만족 체감).

## 26. 재방문 (Revisit)

**[게임 처리 — 다음날 스폰 롤]**
```
RevisitChance = base(0.2)
  + satisfaction/100 × 0.5           // 만족 90 → +0.45
  + favoriteFoodServed ? +0.1
  + preferredSeatUsed ? +0.1
  + regularStageBonus                // 단골일수록 대폭↑
  − daysSinceLastVisit × 0.02
clamp(0.05, 0.95)
```
`DayManager` 다음날 준비 시 각 발견 고양이에 대해 롤 → 방문 큐 편성.

**[플레이어 정보]** "오늘 올 것 같은 단골" 힌트(단골만), 실제 등장은 관찰로 확인.

**[저장 — 만족도 단일 소스(P5)]** 만족도는 **`CatSaveData.satisfactionHistory: float[]`(최근 N=5회)** 한 곳에만 저장한다. 아래는 모두 **파생 계산**(저장 안 함):
```
lastSatisfaction = satisfactionHistory.Last()      // 재방문 롤에 사용
avgSatisfaction  = satisfactionHistory.Average()   // 단골 승급에 사용(27장)
```
그 외 저장: `visitCount`, `lastVisitDay`. → 만족도 관련 중복 필드 제거.

**[예외]** 미발견(첫 등장 전) 고양이는 `spawnWeight` 기반 신규 등장 테이블에서 처리.

## 27. 단골 (Regular) — 이야기가 변하는 축

**[핵심 규칙]** 단골은 숫자가 아니라 **행동·이야기의 변화**로 표현.

**[단계 정의]**

| 단계 | 명칭 | 승급 조건(가정) | 변화(보상) |
|---|---|---|---|
| 1 | 첫 방문 | 발견 | 기본 |
| 2 | 자주 옴 | 누적 방문 ≥3 & `avgSatisfaction` ≥60 | 방문빈도↑, 고정 선호좌석 착석 경향 |
| 3 | 익숙함 | 방문 ≥6 & 취향 2축 Recorded | 특정 행동 증가(전용 idle 모션), 첫 개인 대사 |
| 4 | 단골 | 방문 ≥10 & 취향 3축 Recorded | **개인 에피소드 이벤트** 해금, 전용 자리 선호 강화 |
| 5 | 최애 손님 | 방문 ≥15 & 에피소드 완료 | 특별 보상(가구/메뉴 레시피/도감 완성), 관계 이벤트 개방 |

**[구현]** `RegularStage`는 `CatSaveData`에 저장. `avgSatisfaction`은 `satisfactionHistory`에서 파생(26장, P5). "취향 N축 Recorded"는 `ObservationRecord`의 `Recorded(✓)` 축 개수(18장 4단계 모델, P4). 승급 판정은 매일 정산 시 `RegularManager.Evaluate(cat)`.

**[플레이어 정보]** 도감·정산에서 단계 뱃지 + "저 고양이가 늘 그 자리에 앉는다" 같은 서술적 변화.

**[예외 — 확정, 부록 J-H]** **단골 강등 없음.** 오랜 미방문에도 `RegularStage`는 유지된다(힐링 톤·스트레스 배제).

## 28. 고양이 관계 (Relationship) `[MVP: 제외 → 정식]`

**[핵심 규칙]** 관계는 취향 시스템을 방해하지 않는 보조 축. **MVP 완전 제외**(핵심 관찰 루프 검증과 무관, 개발기간 증가 요인 — P8). 정식 버전에서 아래 최소 형태로 도입, 이후 확장.

**[게임 처리 (MVP 최소)]**
```
같은 시간대 동시 체류 + 근접 좌석 → RelationScore += 소량(일 1회 상한)
RelationScore 임계 도달 → 관계단계 상승(지인→친구)
```

`relationshipHints`로 잠재 짝을 제한(폭발적 조합 방지).

**[플레이어 정보]** 관계 발생 시 하트/말풍선, 도감 관계 탭.
**[예외]** 성향 상충(내향 × 사교) 페어는 관계 상승 지연/불가 설정 가능.

## 29. 일일 상황 (Daily Situation) `[MVP: 제외 → 정식]`

**[목적]** 매일 변주. 단, 플레이어 전략을 무력화하지 않는 **약한 보정**. **MVP 제외**(P8): 관찰 루프 검증 단계에서는 변주가 인과 학습을 방해할 수 있으므로 정식 버전부터 도입.

**[상황 예 → 효과(임시 보정)]**

| 상황 | 효과 |
|---|---|
| 비 오는 날 | 전역 조용함+, 따뜻한 음식(Warm태그) 선호+ |
| 주말 | 손님 스폰량+20% |
| 동네 축제 | 활기참+, 특별 손님 등장확률+ |
| 한파 | 따뜻한 음식 선호+ |
| 고양이 모임 | 사교 성격 고양이 등장 비중+ |
| 유명 고양이 방문 | 1회성 특별 손님 이벤트 |

**[게임 처리]** 하루 시작 시 `SituationManager`가 1개 선택(가중치·중복 방지). 보정은 만족도·스폰·분위기에 임시 가산, 하루 종료 시 소멸.

**[핵심 규칙]** 상황은 취향 Truth를 바꾸지 않는다(선호 "강도"만 임시 가감). 39장 6번(랜덤이 전략 무력화) 방지: 보정 상한을 취향 신호보다 작게.

**[플레이어 정보]** 영업 준비 화면에 "오늘의 상황" 카드.

## 30. 이벤트 (Event)

**[분류]** (a) 개인 에피소드(단골 4~5단계, 스크립트형), (b) 관계 이벤트, (c) 일일 상황(29장), (d) 특별 손님.

**[데이터: `CatEventData`]** `eventId`, `trigger`(단골단계/관계/방문수/날짜), `scriptLines`(대사), `reward`(가구/메뉴/골드/도감).

**[게임 처리]** `EventManager`가 정산·방문 시 트리거 조건 평가 → 조건 충족 시 큐잉 → 다음 방문/정산에서 재생. 1회성 이벤트는 `completed` 플래그 저장.

**[플레이어 정보]** 이벤트 알림, 대사 UI, 보상 팝업.
**[예외]** 트리거 충족했으나 대상 미방문 → 대기 유지(만료 없음, MVP).

## 31. 카페 성장 (Cafe Growth)

**[핵심 규칙]** 골드만으로 전부 해금하지 않는다. **골드 + 발견 + 단골**을 조합해 "관찰 성과"가 성장의 열쇠가 되게 함.

**[레벨 정의(가정)]**

> **P3 반영 — 데드락 방지**: 승급 조건을 "결과(Recorded 취향 N축)"로만 두면, 관찰은 가구가 있어야만 가능하므로(15장) 플레이어가 가구를 안 사면 골드가 넘쳐도 영구히 막힐 수 있다. 각 레벨은 **항상 도달 가능한 대체 경로(OR)** 를 병기하고, 막힌 조건에는 힌트를 노출한다.

| Lv | 내용 | 승급 조건(복합, OR 경로 포함) |
|---|---|---|
| 1 | 작은 카페(4석) | 시작 |
| 2 | 좌석 증가·새 가구 슬롯 | Gold **AND** 발견 고양이 ≥2 |
| 3 | 새 시설·신규 고양이 등장 | Gold **AND** (취향 3축 Recorded **OR** 가구 5종 이상 설치) |
| 4 | 새 공간·관계 확장 | Gold **AND** (단골 ≥2 **OR** 누적 영업일 ≥N) |
| 5 | 특수 시설·희귀 고양이 | Gold **AND** 단골 ≥4 **AND** 에피소드 ≥1 |

**[게임 처리]** `CafeManager.TryUpgrade()`가 복합 조건 검사. 승급 시 배치 가능 영역·가구 슬롯·스폰 테이블 확장.

**[플레이어 정보]** 성장 화면에 조건 체크리스트("골드 ✓ / 단골 1/2") + **막힌 조건 힌트**("취향을 더 발견하려면 새로운 가구를 놓아보세요") — 관찰을 성장 동력으로 인식시키되 원인을 안내.

**[근거]** 39장 관점: 돈→비싼가구 반복 방지 + 성장이 관찰 진척과 묶이되, 초심자가 원인 모른 채 멈추지 않도록 OR 경로 보장.

## 32. 고양이 해금 (Unlock)

**[규모 3단계 제안]**

| 규모 | 고양이 수 | 비고 |
|---|---|---|

**[MVP]** 3마리(치즈/삼색/젖소) 확정 + 여유 시 2마리.

## 36. UI (화면 목록·정의)

각 화면은 **[목적/진입/주요 UI/버튼/표시정보/입력/다음화면]** 으로 정의.

**[화면 목록]** 타이틀 · 세이브/로드 · 카페(플레이) · 영업준비 · 메뉴관리 · 가구구매 · 가구배치 · 고양이정보 · 관찰(실시간) · 관찰기록/정리 · 하루정산 · 카페성장 · 도감 · 설정 · 일시정지.

**[대표 화면 정의 예]**

**카페(플레이)**
- 목적: 영업·관찰. 진입: 영업시작. 주요 UI: 시계/시간대, 매출바, 손님수, 주문티켓, 손님 말풍선.
- 입력: WASD 이동, 좌클릭/E 상호작용, Tab 도감, ESC 일시정지.
- 다음: 영업종료→하루정산.

**하루 정산 / 관찰 정리**
- 목적: 매출 확인 + 취향 기록. 진입: 영업종료.
- 표시: 매출/원가/순익, 고양이별 관찰 요약 카드, [기록하기].
- 다음: 구매 화면.

**가구 배치**
- 목적: 그리드 배치. 표시: 배치 그리드, 가구 인벤토리, 분위기 미터 실시간 프리뷰.
- 입력: 드래그 배치, 회전(R), 삭제.
- 예외: 충돌/공간부족 시 배치 거부 피드백.

**도감** / **고양이 정보**: 34장 참조.

(전체 15개 화면 상세표는 별도 `UI_Text` 테이블·부속 문서로 확장; MVP는 굵게 표기된 화면 우선.)

## 39. 저장 (Save)

**[저장 방식 — 확정, 부록 J-J]** JSON 직렬화 파일, `Application.persistentDataPath`. **MVP는 단일 오토세이브**(하루 정산 완료 시 자동 저장), **정식 버전은 오토세이브 + 수동 슬롯**.

**[필수 저장 항목]**

| 그룹 | 필드 |
|---|---|
| 플레이어 | Gold, 진행도, (능력 단계) |
| 카페 | 레벨, 보유 가구, 배치 좌표, 시설 |
| 메뉴 | 해금/보유 |
| 고양이 | 방문횟수, 만족도 이력, 단골단계, 관계 |
| **관찰** | **발견한 취향(ObservationRecord), 관찰 단서 상태** |
| 이벤트 | 발생/완료 플래그, 진행도 |
| 도감 | 발견 상태, 완성도 |
| 일자/상황 | currentDay, 진행 위상 |

**[절대 규칙]** **플레이어가 발견한 취향(ObservationRecord)은 반드시 저장**. Truth(CatData)는 데이터 원본이라 저장 불필요.

**[저장 시점]** 하루 정산 완료 시 오토세이브 + 수동 저장. 무결성 위해 임시파일→교체 방식.

**[QA 연동]** "종료→재실행→기록 유지"는 필수 테스트(45장).

## 40. 데이터 구조 (Data Architecture)

**[권장 방식]** **ScriptableObject 중심** + 대량/반복 데이터는 CSV→SO 임포트 하이브리드.

| 데이터 | 저장 형식 | 이유 |
|---|---|---|
| Cat/Furniture/Menu/Event 정의 | ScriptableObject | 에디터 친화, 참조 안전, 태그 enum 활용 |
| 밸런스 수치 테이블(가격·확률) | CSV/JSON → SO 임포트 | 대량 튜닝·외부 편집 용이 |
| 로컬라이즈 텍스트 | CSV/Unity Localization | 번역 워크플로 |
| 런타임 세이브 | JSON | 가독·디버깅 |

**[근거]** 순수 CSV/DB는 1인+AI 환경에서 참조 검증이 약함. SO는 오타·누락을 에디터에서 조기 발견. **결정 권장: SO 우선, 밸런스만 CSV.** (`[미결정]` 아님 — 권장 확정, 단 팀 취향에 따라 조정 가능)

**[핵심 원칙]** 새 콘텐츠 = SO 에셋 1개 추가로 끝. 매니저 코드 무수정(태그·조건 데이터 기반 처리).

## 45. QA (테스트 케이스)

> 핵심 규칙별 케이스. 실제 40+개 확보 목표. 아래는 대표 세트.

**[좌석/fallback]**
1. 창가석 없음 → 치즈냥 일반석 fallback, 좌석 축 `?` 유지(약한 단서만).
2. **[P1]** 창가석 없이 치즈냥 여러 날 방문 → 일반석 fallback 단서 누적이 **cap 2에서 정체 → Suspected(≥3) 미승격 → 가짜 "일반석 선호" 가설이 생기지 않음.**
3. 창가석 존재 → 치즈냥 창가석 선택, 창밖 응시 단서 생성.
4. 창가석 만석 → 차선 좌석 선택, 창가 단서 미생성.
5. 창가석 반복 관찰 → weight≥7 & 우세 → **Confirmable(★)** 도달.

**[시설]**
6. 캣타워 없음 → 삼색냥 캣타워 취향 관찰 불가.
7. 캣타워 설치 → 삼색냥 이용확률↑, ClimbTop 단서 생성.
8. 시설 점유 중 → 대기 또는 대체 행동.

**[음식]**
9. 생선케이크 제공 → 치즈냥 완식·빠름 → 강한 음식 단서.
10. 최애 품절 → 차선 주문, 음식 만족 하락.

**[관찰/기록/저장 — 4단계 모델 P4]**
11. **[P4]** Suspected(`…`) 상태에서는 '기록' 버튼 **비활성**(관찰 더 필요 표시).
12. **[P4]** Confirmable(`★`) 상태에서 '기록' 클릭 → `Recorded(✓)`, 도감 반영 + 발견 연출·보너스(P9).
13. 게임 종료→재실행→`ObservationRecord`(Recorded 상태 포함) 유지.
14. Truth는 세이브 파일에 존재하지 않음(파일 검사).

**[성장/데드락 P3]**
15. **[P3]** 골드 충분·가구 미구매로 취향 3축 미Recorded → Lv3 승급이 **가구 5종 설치 OR 경로**로 가능(영구 데드락 없음). 성장 화면에 원인 힌트 노출.

**[회전율 P7]**
16. **[P7]** 느긋한 치즈냥 장기 착석 → `maxSitDuration` 도달 시 Pay 전이(자리 무한 독점 없음). 동시 체류 < 좌석 수 유지 확인.

**[분위기 P2]**
17. **[P2]** MVP: 분위기 변화가 만족도에 영향 없음(atmoMult=1.0). 정식: 선호 분위기 지배 시 좌석·시설 만족 ×1.1 / 반대 ×0.9 확인.

**[만족/재방문/단골]**
18. 취향 3축 충족 → 만족 90+ → 재방문확률 대폭↑.
19. 방문10·3축 Recorded → 단골4 승급 → 개인 에피소드 큐잉.

**[분위기/상황 — 정식 버전 대상]**
20. 캣타워 다수 → 활기참 지배(DominantAxis) → 조용함 선호 치즈냥 만족 ×0.9 확인.
21. (정식) 비 오는 날 보정이 취향 순위를 뒤집지 않음(전략 보존).

**[관계 — 정식 버전 대상]**
22. (정식) 젖소냥·치즈냥 동시간·근접 반복 → 관계 상승 → 인접 착석 경향.

**[예외/안정성]**
23. 전 좌석 만석 신규 고양이 → 대기/포기 규칙 동작(P7: 통상 만석 미발생하도록 스폰 조정).
24. 사용 중 가구 삭제 → 고양이 상태 안전 종료·재탐색.
25. 서빙 지연 → 인내심 0 → 불만 퇴장·페널티 반영.

## 46. 튜토리얼 (Tutorial)

**[목적]** 첫 세션 안에 "가설→구매→검증 성공" 1사이클을 반드시 경험시켜 핵심 재미를 각인.

```
2) 치즈냥 방문 → 창밖 응시 행동 강조 연출("치즈냥이 창밖을 오래 보네?")

6) 자유 플레이 진입
```

**[규칙]** 정답을 직접 알려주지 않는다. **힌트는 방향만**(어떤 축을 시도할지) 제시, 취향 자체는 노출 금지.

**[개발 고려]** 튜토리얼은 데이터 스크립트(EventData)로 구성해 스킵/재생 가능하게.

## 49. 개발 순서 (리스크 우선 재정렬)

> 원안(순차)보다 **핵심 재미를 가장 빨리 검증**하도록 재배치. "관찰 루프"를 최우선 수직 슬라이스로.

**[Phase 0 — 기반]**
1. 프로젝트 셋업/입력/카메라(줌 필수)
2. 카페 공간·그리드·좌석 배치(에디터에서 수동 OK)

**[Phase 1 — 수직 슬라이스: 관찰 루프 (최우선)]**
3. `CatData` SO + 좌석 태그 시스템
4. 고양이 스폰·이동·FindSeat/Sit(SeatScore + **fallback**)
5. `ObservationManager` 단서 기록(콘솔 로그 수준으로 먼저)
6. 가구 배치(런타임) → 좌석/시설 등록 → 분위기 재계산
7. 시설 이용 행동 + 단서
8. 하루 종료 → 관찰 정리 → **취향 기록** → 저장/로드
9. **여기서 1차 플레이테스트**(46장 질문 검증). ← 가장 중요한 게이트

**[Phase 2 — 경영 살]**
10. 주문·원탭 조리·서빙·결제·골드·정산
11. 만족도 → 재방문 → 간단 단골
12. 상점(가구/메뉴 구매)·카페 성장(복합 조건)

**[Phase 3 — 콘텐츠·정식화]**
13. 관계·이벤트·일일 상황·에피소드
14. UI 정식화·튜토리얼·연출/애니·사운드
15. 밸런스·QA·Steam 연동(업적/저장)

**[리스크 근거]** 조리/경제보다 **관찰-fallback-재관찰 루프**가 게임 성패를 결정하므로 최우선 검증. 조리는 원탭이라 저리스크→후순위.

1. **한 문장 설명?** — 고양이 손님의 숨겨진 취향을 행동 관찰로 추리해 카페를 그에 맞게 바꿔가는 관찰·추리형 고양이 카페 경영 시뮬.
2. **핵심 재미?** — 정보 비대칭(숨겨진 취향)을 관찰→추론→환경변경→재관찰로 해소하며 "이 고양이를 이해했다"는 성취를 얻는 것.
3. **일반 손님과 차이?** — 돈 지불 NPC가 아니라 고정 취향·성격·관계·이야기를 가진 해독 대상이자 게임의 핵심 콘텐츠.
4. **왜 관찰하나?** — 취향이 숨겨져 있고 직접 볼 수 없어, 관찰만이 만족도·재방문·단골·성장으로 가는 유일한 경로.
5. **왜 가구를 사나?** — 가구가 없으면 그 취향 축은 관찰조차 불가. 가구는 스탯이 아니라 "새 행동을 볼 수 있는 관찰 채널".
6. **왜 돈을 버나?** — 관찰 채널(가구)·메뉴·카페 확장을 여는 수단. 돈은 목적이 아니라 이해의 부산물이자 재투자 자원.
7. **왜 새 메뉴가 필요?** — 음식 취향(최애/계열) 축을 관찰·충족해 만족도를 올리고 새 고양이 등장·취향을 여는 채널.
8. **왜 새 고양이를 만나고 싶나?** — 각자 다른 취향·성격·특수행동·에피소드를 가진 새 퍼즐이자 도감 수집 목표.
9. **왜 단골을 만들고 싶나?** — 단골은 숫자가 아니라 행동·대사·개인 에피소드의 변화. "내 카페의 이야기"가 쌓임.
10. **왜 다음날 플레이?** — 환경 변경의 결과(새 행동)는 다음날 방문에서 확인되고, 재방문·단골·관계가 하루 단위로 진전.
11. **왜 1시간+ 플레이?** — 취향 확정은 반복 관찰(누적 weight)로만 도달하고, 단골·관계·도감 완성이 장기 목표를 형성.
12. **행동이 의미 있는 정보를 주나?** — 예. 모든 행동은 태그 기반 단서(강/약)로 기록되어 추론에 직접 쓰이며, fallback은 약하게 남아 정정 가능.
13. **추론 과정이 재미있나?** — Phase1 플레이테스트로 최우선 검증. 힌트는 방향만 주고 정답 비노출로 "발견의 쾌감" 유지.
14. **경영과 관찰이 분리되나?** — 아니오. 카페 성장이 골드+발견+단골 복합조건(31장)이라 두 축이 구조적으로 결속.
15. **"귀여운 카페"에서 끝나나?** — 아니오. 관찰-추리 루프 + 단골 이야기 변화 + 관계로 정서적 깊이를 만든다.
16. **1인+AI로 가능한가?** — 예. 데이터 주도·태그화·원탭 조리·상태 최소·규모 3단계·패널 전환으로 제작량을 통제.

## 부록 Z. 최종 우선순위 정리 (A~J)

### A. 반드시 만들어야 하는 시스템 (없으면 게임 성립 X)
- 숨겨진 취향(Truth) ↔ 관찰(Observed) 분리
- 좌석/시설 fallback 행동
- 관찰 단서 기록·추론·기록 확정 파이프라인
- 가구=관찰 채널(미보유 시 관찰 불가)
- 저장(특히 ObservationRecord)

### B. MVP에서 만들어야 하는 시스템
- 방문·좌석선택(fallback + 단서 cap, P1)·주문·원탭조리·서빙·결제·골드
- 관찰(3축)·취향기록(4단계 모델 P4)·도감(간이)·가구구매/배치·분위기(시각효과만, P2)
- 만족도(단일 소스 P5)·간단 재방문·간단 단골(2~3단계)·저장·튜토리얼 1사이클
- **MVP 제외(P8)**: 관계·일일 상황·MoveSeat/Social·분위기 만족 승수·음식 계열 판정

### C. 정식 버전에서 추가할 시스템
- 관계(28장)·일일 상황(29장)·개인 에피소드·이벤트
- 분위기 만족 승수·음식 계열(preferredTags) 판정·국소 분위기
- 카페 성장(복합조건 full, OR 경로 P3)·플레이어 소폭 성장
- Steam 업적/통계·다중 세이브·튜토리얼 정식화

### D. 향후 업데이트로 미룰 시스템
- 시즌/계절, 관계 그룹·삼각관계, 테마 리노베이션, 사진 모드, 모바일 이식, 커스텀 콘텐츠

### E. 삭제(하지 않는 것)가 좋은 시스템
- 온라인/친구 카페 방문, 캐시샵/광고/모바일 BM, 이중 재화
- 복잡한 조리 미니게임(노동화), 복잡한 직원 시스템, 대규모 스토리/컷신
- 수치로만 보여주는 취향/단골(감정 저하)

### F. 개발 난이도가 높은 시스템
- CatBrain(HFSM/분기·반복 억제)
- 관찰 추론 승격 로직(단서 weight·정정)
- 배치→좌석/시설/분위기 재계산 연동
- 세이브 무결성·버전 관리

### G. 핵심 재미와 직접 연결되는 시스템 (품질 최우선)
- 관찰 단서 연출(행동의 가독성)
- fallback vs 진짜 취향의 구분감
- 취향 발견 순간의 피드백(도감 ✓, "역시!" 연출)
- SeatScore/UseChance에서 취향 신호가 노이즈를 압도

### H. 개발자가 가장 먼저 구현할 시스템 (49장 Phase1)
1. CatData + 좌석 태그 → 2. 스폰·FindSeat·fallback → 3. ObservationManager(로그) → 4. 런타임 가구 배치·재계산 → 5. 시설 행동·단서 → 6. 관찰 정리·기록·저장 → **7. 1차 플레이테스트 게이트**

### I. 첫 프로토타입에서 검증할 것
> "행동 관찰→원인 추측→환경 변경→새 행동 발견"이 재미있는가?
관측 지표: 관찰 여부, 가설 발화, 가구 구매 시도, 변화 관심, 발견 만족, 새 고양이 호기심, 도감 열람, **돈만 벌고 고양이 무시 여부(=적신호)**.
